## Why

竞品分析显示，2xapi 已经具备本地网关、多客户端托管、供应商代理、用量统计、插件生态和基础会话修复，但缺少可组合的配置档案、统一的供应商能力诊断，以及可暂停/恢复的会话修复任务。此前会话修复出现长时间停在中间进度，供应商切换也需要用户在多个入口之间手工确认，说明 P0 应优先补齐配置编排与可观察性。

本变更吸收 cc-switch 的项目快照、Provider Doctor、健康监控思路，以及 Codex++ 的官方登录/混入 API/纯 API 模式分层；同时把现有“官方登录凭据只读”作为硬边界，确保新增能力不会删除、覆盖或解析 `auth.json`。

## What Changes

- 新增命名配置档案：按 Codex/Claude 等客户端保存供应商、模型、协议、代理、加速线路和生态开关，并支持预览、原子应用、失败回滚。
- 明确 Codex 四种连接模式：官方直连、官方登录保留 + 2xapi 网关、纯 API、聚合故障转移；普通切换不触碰官方凭据。
- 升级 Provider Doctor：增加协议、认证、模型列表、最小真实请求、流式/工具能力、延迟和错误分类，输出脱敏诊断结果。
- 新增供应商级健康状态、熔断和受控故障转移；官方账号请求不得自动转移到第三方账号。
- 将会话修复改为可观察任务：支持预览、取消、断点恢复、幂等重试、单项失败隔离和最终统计。
- 更新项目书、API 契约和验收清单，补充迁移、回滚和安全约束。

## Capabilities

### New Capabilities

- `config-profiles`: 命名配置档案、预览、原子应用和回滚。
- `provider-doctor`: 供应商多阶段能力诊断、错误分类和健康状态。
- `session-repair-jobs`: 会话修复任务的预览、进度、取消、恢复和幂等执行。

### Modified Capabilities

（无。本变更的官方登录保护约束作为新能力的验收条件写入各自规格，不改变既有主规格文件。）

## Impact

- 后端：新增档案与诊断/任务服务，扩展 `providers.json`/私有状态文件和 HTTP API；复用现有原子写、CAS、备份、Provider Store、会话扫描器和网关状态。
- 前端：新增配置档案入口、Doctor 结果面板、健康状态和会话修复任务控制；保留现有连接页与会话管理的信息架构。
- 数据：新增版本化、可迁移的本地元数据；不在档案、诊断、日志或任务状态中保存 API Key、OAuth token、Cookie、Authorization、prompt 或响应正文。
- 兼容：旧供应商、旧会话和现有官方登录状态保持不变；未确认归属的配置只读提示，不自动覆盖。
