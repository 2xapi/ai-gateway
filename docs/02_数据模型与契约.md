# 02 数据模型与契约（冻结）

> 本文档是**冻结契约**。M1（数据层）字段必须与本表 100% 一致；M2（Config 引擎）生成结果必须与 §5 契约表逐字段一致。
> 与 01 的行为矩阵配套使用：01 定「行为」，02 定「数据与产物」。

---

## 1. Provider 数据模型

```rust
pub struct Provider {
    // ── 基础 ──
    pub id: String,                       // uuid v4，主键
    pub name: String,                     // 显示名，非空
    pub icon: Option<String>,             // 图标标识/emoji
    pub icon_color: Option<String>,       // 图标颜色 hex
    pub sort_index: i64,                  // 列表排序
    pub created_at: i64,                  // unix 秒
    pub website_url: Option<String>,      // 官网
    pub notes: Option<String>,            // 备注

    // ── 连接 ──
    pub base_url: String,                 // 上游 API 地址（Official 可留空）
    pub api_key: String,                  // API Key（Official 可留空）
    pub access_mode: AccessMode,          // Official | Mixed | PureApi

    // ── 协议 ──
    pub wire_api: WireApi,                // Responses | ChatCompletions
    pub user_agent: Option<String>,       // 自定义 UA

    // ── 模型 ──
    pub model: String,                    // 默认模型名
    pub models: Vec<ModelConfig>,         // 模型列表
    pub context_window: Option<String>,   // 显示用上下文窗口

    // ── 网络 ──
    pub proxy_url: Option<String>,        // per-provider HTTP 代理
    pub timeout_secs: Option<u64>,        // 默认 120

    // ── Sub2API（本期 stub，见 01-D6）──
    pub sub2api_enabled: bool,
    pub sub2api_multiplier: f64,

    // ── 高级 ──
    pub custom_headers: Option<HashMap<String, String>>,
    pub config_toml_snapshot: Option<String>,  // 应用时生成的 config.toml 快照（审计/回看）
    pub auth_json_snapshot: Option<String>,    // 应用时生成的 auth.json 快照（审计/回看）
}

pub enum AccessMode { Official, Mixed, PureApi }
pub enum WireApi { Responses, ChatCompletions }

pub struct ModelConfig {
    pub name: String,                     // 模型 id
    pub display_name: Option<String>,
    pub context_window: Option<u64>,      // tokens
    pub is_multimodal: bool,
    pub send_as_is: bool,                 // 是否原样透传（不做映射）
}
```

## 2. 字段约束与校验规则

| 字段 | 规则 |
|---|---|
| `id` | uuid v4，创建时生成，不可变 |
| `name` | 非空，1~40 字符 |
| `base_url` | `access_mode != Official` 时**必填**且必须是合法 `http(s)://` URL，末尾不带 `/` |
| `api_key` | `access_mode != Official` 时**必填**，非空 |
| `access_mode` | 三选一，默认 `PureApi` |
| `wire_api` | 二选一，默认 `Responses` |
| `model` | 非空，且应存在于 `models` 列表（警告级，不阻断） |
| `timeout_secs` | `None` 时按 `120`；有效范围 5~3600 |
| `sub2api_multiplier` | `> 0`，默认 `1.0` |
| `sort_index` | 新建时 = 当前最大值 +1 |
| `config_toml_snapshot`/`auth_json_snapshot` | 每次 `apply` 成功后写入本次产物快照 |

校验失败 → CRUD 返回 422 + 字段级错误信息（见 04 错误码）。

## 3. providers.json 存储格式

存储位置：`~/.codex/2xapi-providers.json`（M0 确定实际路径）。

```json
{
  "schema_version": 1,
  "active_provider_id": "uuid-of-active",
  "providers": [
    { "id": "...", "name": "...", "access_mode": "Mixed", "...": "..." }
  ]
}
```

- `schema_version`：版本号，后续迁移用，本期 = 1。
- `active_provider_id`：当前激活 provider；`null` 表示未激活（Official）。
- 读写必须原子（写临时文件 → rename），避免半写损坏。

## 4. AccessMode / WireApi 取值约定（序列化）

| 枚举 | 序列化字符串（JSON/TOML） |
|---|---|
| `AccessMode::Official` | `"official"` |
| `AccessMode::Mixed` | `"mixed"` |
| `AccessMode::PureApi` | `"pure_api"` |
| `WireApi::Responses` | `"responses"` |
| `WireApi::ChatCompletions` | `"chat_completions"` |

> 注意：与 v2 文档里的 `experimental_bearer_token` 等无关；序列化字符串前端、后端、存储三方必须统一为本表。

## 5. config.toml / auth.json 契约表（冻结，M2 验收依据）

> `{var}` 表示用 Provider 字段替换。三个模式各给完整产物。

### 5.1 Official 模式

**config.toml**（写入 `~/.codex/config.toml`）：
```toml
model_provider = "openai"
model = "{provider.model}"
# [model_providers.custom] 段落删除
```

**auth.json**：**不动**（保留官方 OAuth）。

### 5.2 Mixed 模式

**config.toml**：
```toml
model_provider = "custom"
model = "{provider.model}"
model_catalog_json = "{catalog_path}"   # 例 ~/.codex/2xapi-model-catalog.json

[model_providers.custom]
base_url = "http://127.0.0.1:8787"
wire_api = "responses"
requires_openai_auth = true
# experimental_bearer_token 不设置（01-D2）
```

**auth.json**：**不动**。

### 5.3 PureApi 模式

**config.toml**：与 5.2 Mixed **完全相同**。

**auth.json**（写入 `~/.codex/auth.json`）：
```json
{
  "OPENAI_API_KEY": "{provider.api_key}",
  "...其他原有字段保留不动..."
}
```
- 仅把 `OPENAI_API_KEY` 字段设为 `provider.api_key`；若字段不存在则新增，其他字段保留。
- **切换前**：若 `auth.json.official.bak` 不存在，则把当前 `auth.json` 原样复制为 `auth.json.official.bak`（01-D4）。

### 5.4 备份/恢复文件

| 文件 | 何时产生 | 内容 |
|---|---|---|
| `auth.json.official.bak` | 首次切换到 PureApi 前 | 当时的 `auth.json` 原样副本 |
| `auth.json`（恢复） | `activate-official` 时 | 用 `auth.json.official.bak` 覆盖回 `auth.json` |

### 5.5 model_catalog_json（模型目录文件）

> ⚙️ **CCR-001（2026-08-14 已同步）**：本节原写的 `{name,provider,context_window}` 是占位格式；
> 真实 Codex 的 `model_catalog_json` 需要**富格式**（slug/base_instructions/priority/…），否则 Codex 不识别。
> 实现已采用富格式（见 `config.rs::build_model_catalog`），本节据此更新。

路径 `{catalog_path}` = `~/.codex/2xapi-model-catalog.json`，由 active provider 的 `models` 生成。富格式（每条）：
```json
{ "slug": "<model.name>", "display_name": "...", "description": "...",
  "base_instructions": "You are Codex, a coding agent. ...",
  "context_window": 200000, "max_context_window": 200000, "effective_context_window_percent": 95,
  "priority": 1000, "wire_api": "responses", "visibility": "list", "supported_in_api": true,
  "input_modalities": ["text"],
  "supported_reasoning_levels": [ {"description":"Disable Thinking","effort":"none"}, {"description":"Enabled Thinking","effort":"high"} ],
  "truncation_policy": {"limit":10000,"mode":"bytes"} }
```
- 仅 Mixed/PureApi 模式写入该字段并生成文件；Official 模式删除该行与文件。
- `context_window` 取 `ModelConfig.context_window`，缺省 200000。

## 6. 第三方中转站 UsageStats 数据模型（新增）

统计数据只覆盖经本地网关转发的 `Mixed` / `PureApi` 请求，不写入 prompt、响应正文或任何凭证。

```rust
pub struct UsageRecord {
    pub request_id: String,              // 单次请求内部 ID，用于流式完成去重
    pub provider_id: String,
    pub model: String,
    pub occurred_at: i64,                // unix 秒
    pub input_tokens: Option<i64>,
    pub output_tokens: Option<i64>,
    pub total_tokens: Option<i64>,
    pub cache_read_input_tokens: Option<i64>,
    pub cost: Option<f64>,
    pub cost_source: CostSource,         // upstream | local_rate | unknown
}

pub enum CostSource { Upstream, LocalRate, Unknown }

pub struct UsageDailySummary {
    pub date: String,                    // 本机时区 YYYY-MM-DD
    pub provider_id: String,
    pub request_count: i64,
    pub input_tokens: Option<i64>,
    pub output_tokens: Option<i64>,
    pub total_tokens: Option<i64>,
    pub cache_read_input_tokens: Option<i64>,
    pub cost: Option<f64>,
    pub cost_source: CostSource,
}
```

### 6.1 规范化与聚合规则

- `total_tokens` 优先使用上游值；缺失时仅在 input/output 均有效时相加，否则保留 `null`。
- 缓存命中率 = `cache_read_input_tokens / input_tokens`；分母为 0 或任一字段缺失时返回 `null`。
- 兼容上游字段：`usage.input_tokens`、`prompt_tokens`、`usage.output_tokens`、`completion_tokens`、`cache_read_input_tokens`、`cache_read_tokens`、`total_tokens`。
- 一个请求只能产生一条完成记录；流式响应中间事件不得重复累计，断流请求不计入已完成用量。
- 日期按本机时区切分，至少保留 90 天；首页摘要和历史页必须查询同一聚合存储。

### 6.2 UsageOverlay 设置模型

悬浮窗设置与现有 `2xapi-settings.json` 共存，写入顶层 `usageOverlay` 段；写入时必须保留文件中的其他设置字段。

```rust
pub struct UsageOverlaySettings {
    pub enabled: bool,                  // 默认 false，不随启动自动显示
    pub opacity: f64,                   // 0.60~1.00，默认 0.88
    pub always_on_top: bool,             // 默认 true
    pub click_through: bool,             // 默认 false
    pub restore_full_opacity_on_hover: bool, // 默认 true
    pub refresh_interval_secs: u64,     // 默认 30，范围 15~300
    pub position: Option<OverlayPosition>,
}

pub struct OverlayPosition {
    pub x: i32,
    pub y: i32,
}
```

校验失败时拒绝保存并返回字段级错误：透明度必须在 `0.60~1.00`，刷新间隔必须在 `15~300` 秒；缺失字段使用默认值。悬浮窗可见状态属于运行时状态，不作为 `enabled` 的替代：`enabled=false` 时启动后不可见，用户主动显示后才创建/显示窗口。

## 8. 验收要点

- M1：`Provider` 序列化/反序列化 round-trip 无损；字段类型与本表一致。
- M2：对三种模式各造一个 Provider，`apply` 后用 `diff` 比对生成的 `config.toml`/`auth.json` 与 §5 逐字符一致（变量替换后）。
- M2：PureApi 切换前后，`auth.json.official.bak` 行为符合 §5.4。
- UsageStats：usage 字段缺失、缓存字段兼容、流式去重、按本机日期聚合和敏感字段不落盘均有测试。
- UsageOverlay：默认关闭、透明度边界、设置保留其他字段、位置记忆和平台不支持时的降级均有测试。
