# 05 里程碑任务清单与验收标准（DoD）

> 这是**执行层核心文档**。每个里程碑给原子任务 `T-x.y` + 完成定义 `DoD` + 验收 Gate。
> API 每完成一条任务即对照其 DoD 自检；整里程碑所有 DoD 满足 + Gate 通过，方可进入下一里程碑（见 00 §6）。

### 用户验收 Checklist（M7）
- [ ] 添加一个 Mixed 模式 provider，激活后 Codex 能用第三方模型对话
- [ ] 切到 PureApi，确认 `auth.json.official.bak` 产生，Codex 仍可用
- [ ] `activate-official` 后 auth.json 恢复，Codex 回到官方
- [ ] 网关热切换：激活另一 provider，**不重启 Codex**，下一请求走新 provider
- [ ] ChatCompletions 模式 provider 能正常对话（协议转换生效）
- [ ] Provider Doctor 三步诊断在「配置正确」provider 上全绿
- [ ] Provider Doctor 在「故意写错 base_url」时 errors 正确汇总
- [ ] config 预览与实际写入一致；用户在 config.toml 手写的其他字段 apply 后仍在
- [ ] per-provider 代理与超时生效（504 可复现）
- [ ] 首页今日摘要可进入使用统计，两个页面数字一致
- [ ] 使用统计能切换中转站并查看近 7/30/90 日历史、模型排行和缓存命中率
- [ ] 上游没有 usage/缓存字段时显示「暂无数据」，不伪造 Token、费用或命中率
- [ ] 流式请求只计数一次，统计数据不包含 prompt、响应正文、Key、Cookie
- [ ] 悬浮窗默认不显示，用户开启后可调透明度（60%~100%），重启后设置保留
- [ ] 悬浮窗收起/展开、拖动、置顶和关闭行为正常；关闭悬浮窗不影响网关和完整统计页
- [ ] 默认鼠标可点击；鼠标穿透为可选高级设置，平台不支持时有明确提示
- [ ] 悬浮窗统计与首页/完整统计页数字一致，不产生重复请求或重复计数
- [ ] 全程无崩溃、无数据丢失
