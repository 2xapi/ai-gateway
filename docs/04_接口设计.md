> 本文档是**冻结契约**。M3/M4/M5 的路由实现、M6 的 `api-client.js` 必须与本表逐字段一致。
> 与 02（数据）、03（FR）、01（行为决策）配套。
>
> **注意：本文档含未收录端点，以代码为准。** 契约章节（§1~§3）未完全覆盖后续迭代新增的路由，前端实际调用的完整端点清单见 §6（代码核对结果）。

## 0. 通道决策与统一约定

**去歧义（v2 提到 IPC，但又列 HTTP 路由）**：本项目统一由内置 **axum HTTP server** 暴露所有接口，前端用 `fetch` 调用 `/api/*`，Codex 调用 `/v1/*`。**不使用 Tauri invoke**，以保持前后端解耦、便于 M6 独立调试。

**统一响应信封**：
```jsonc
// 成功（HTTP 2xx）
{ "ok": true, "data": <T> }
// 失败（HTTP 4xx/5xx）
{ "ok": false, "error": { "code": "E_XXX", "message": "...", "fields": ["base_url"] } }
```

**Base URL**：管理接口与网关同源 `http://127.0.0.1:8787`。

### 1.5 使用统计（第三方中转站）

统计接口只返回经本地网关产生的第三方中转用量；不统计 Official 直连请求。查询失败不影响网关转发。

| # | 方法 | 路径 | 请求体/查询 | 响应 data | FR |
|---|---|---|---|---|---|
| 12 | GET | `/api/usage/summary` | `provider_id?`, `date?`（默认今天） | `UsageSummary` | FR-10.4 |
| 13 | GET | `/api/usage/history` | `provider_id?`, `days=7|30|90` | `UsageDailySummary[]` | FR-10.5 |
| 14 | GET | `/api/usage/models` | `provider_id?`, `days=7|30|90` | `UsageModelSummary[]` | FR-10.6 |
| 15 | POST | `/api/usage/refresh` | `{ provider_id?: string }` | `{ synced_at, source, warning? }` | FR-10.7/10.9 |

**`UsageSummary`：**
```ts
{
  date: string, provider_id: string | null, request_count: number,
  input_tokens: number | null, output_tokens: number | null,
  total_tokens: number | null, cache_read_input_tokens: number | null,
  cache_hit_rate: number | null, cost: number | null,
  cost_source: "upstream" | "local_rate" | "unknown",
  synced_at: string
}
```

**`UsageDailySummary`：** `{ date, provider_id, request_count, input_tokens, output_tokens, total_tokens, cache_read_input_tokens, cache_hit_rate, cost, cost_source }`。

**`UsageModelSummary`：** `{ model, request_count, input_tokens, output_tokens, total_tokens, cache_read_input_tokens, cache_hit_rate, cost, share }`。

规则：缺失的 Token、缓存或费用字段返回 `null`；前端显示「暂无数据」。接口不得返回 prompt、响应正文、Authorization、API Key 或 Cookie。

### 1.6 悬浮窗设置

悬浮窗设置属于本机应用设置，不写入 Provider，不影响网关转发。

| # | 方法 | 路径 | 请求体/查询 | 响应 data | FR |
|---|---|---|---|---|---|
| 16 | GET | `/api/settings/usage-overlay` | — | `UsageOverlaySettings` | FR-11.1/11.3/11.5 |
| 17 | PUT | `/api/settings/usage-overlay` | `UsageOverlaySettings` | 保存后的 `UsageOverlaySettings` | FR-11.2/11.5/11.6 |
| 18 | POST | `/api/settings/usage-overlay/action` | `{ action: "show"|"hide"|"toggle" }` | `{ visible: boolean }` | FR-11.2/11.6 |

`GET` 在没有设置时返回默认值：`enabled=false`、`opacity=0.88`、`always_on_top=true`、`click_through=false`、`restore_full_opacity_on_hover=true`、`refresh_interval_secs=30`。`PUT` 必须校验范围并原子保留 `2xapi-settings.json` 其他段。`action=show` 只在用户主动操作时显示窗口；应用启动不得因为该接口自动显示。

## 2. 网关接口 `/v1/*`（Codex 调用）+ 健康

| # | 方法 | 路径 | 说明 | FR |
|---|---|---|---|---|
| 19 | GET | `/health` | 健康检查 | FR-4.1 |
| 20 | POST | `/v1/responses` | Responses 代理（Codex 默认入口） | FR-4.3~4.6 |
| 21 | POST | `/v1/chat/completions` | Chat 代理（直传或反向转换） | FR-4.5/4.6 |
| 22 | GET | `/v1/models` | 模型列表代理 | FR-7.1 网关侧 |

**`/health` 响应**：`{ status: "ok", active_provider_id: string|null, access_mode: "official"|"mixed"|"pure_api"|null }`

**网关行为**（由 active provider 的 access_mode + wire_api 决定，见 01 §4/§5、03 FR-4）：
- 注入 `Authorization: Bearer {provider.api_key}`、`User-Agent`、`custom_headers`；
- `wire_api=responses` → 转发到 `{base_url}/responses`，body 原样；
- `wire_api=chat_completions` → 请求/响应做 Responses↔Chat 转换（含 SSE）；
- 上游错误原样透传；超时返回 504。

**`/v1/responses` 的请求体**：原样 Codex Responses 请求（`input`/`instructions`/`model`/`stream`...），网关不解析、不修改（除非需转换）。

## 3. 错误码表

| code | HTTP | 含义 |
|---|---|---|
| `E_VALIDATION` | 422 | 字段校验失败（fields 标注） |
| `E_NOT_FOUND` | 404 | 资源不存在 |
| `E_BAD_REQUEST` | 400 | 参数缺失/格式错 |
| `E_UPSTREAM` | 502 | 上游返回错误 |
| `E_TIMEOUT` | 504 | 上游/请求超时 |
| `E_INTERNAL` | 500 | 未预期内部错误 |

## 4. TypeScript 类型汇总（供 `api-client.js` 直接使用）

```ts
type AccessMode = "official" | "mixed" | "pure_api";
type WireApi = "responses" | "chat_completions";

interface ModelConfig {
  name: string; display_name?: string;
  context_window?: number; is_multimodal: boolean; send_as_is: boolean;
}

interface Provider {
  id: string; name: string; icon?: string; icon_color?: string;
  sort_index: number; created_at: number; website_url?: string; notes?: string;
  base_url: string; api_key: string; access_mode: AccessMode;
  wire_api: WireApi; user_agent?: string;
  model: string; models: ModelConfig[]; context_window?: string;
  proxy_url?: string; timeout_secs?: number;
  sub2api_enabled: boolean; sub2api_multiplier: number;
  custom_headers?: Record<string, string>;
  config_toml_snapshot?: string; auth_json_snapshot?: string;
}

interface DiagnoseResult {
  configValid: boolean; reachable: boolean; latencyMs: number | null;
  models: ModelConfig[]; testOk: boolean;
  errors: { step: "config"|"connect"|"request"; code: string; message: string }[];
}

interface PreviewResult {
  config_toml: string;
  auth_action: "noop" | "set_key";
  auth_diff: string[] | null;
  backup_will_create: boolean;
}

interface ActivateResult {
  active_provider_id: string; config_written: boolean;
  auth_changed: boolean; backup_created: boolean;
}

interface UsageSummary {
  date: string; provider_id: string | null; request_count: number;
  input_tokens: number | null; output_tokens: number | null;
  total_tokens: number | null; cache_read_input_tokens: number | null;
  cache_hit_rate: number | null; cost: number | null;
  cost_source: "upstream" | "local_rate" | "unknown"; synced_at: string;
}

interface UsageDailySummary extends UsageSummary {}

interface UsageModelSummary {
  model: string; request_count: number;
  input_tokens: number | null; output_tokens: number | null;
  total_tokens: number | null; cache_read_input_tokens: number | null;
  cache_hit_rate: number | null; cost: number | null; share: number | null;
}

interface UsageOverlaySettings {
  enabled: boolean; opacity: number; always_on_top: boolean;
  click_through: boolean; restore_full_opacity_on_hover: boolean;
  refresh_interval_secs: number; position: { x: number; y: number } | null;
}

interface ApiOk<T>  { ok: true;  data: T }
interface ApiErr    { ok: false; error: { code: string; message: string; fields?: string[] } }
type ApiResult<T> = ApiOk<T> | ApiErr;
```

## 5. 验收要点

- 每个接口必须有 happy path + 至少一个错误分支的测试。
- `activate` 的三个布尔字段（config_written/auth_changed/backup_created）必须按 01-D4/FR-2.5 准确反映。
- `/v1/responses` 在 `wire_api=chat_completions` 下的转换，需用 fixture 验证 round-trip（FR-5.4）。
- 使用统计接口必须验证 provider/date/days 筛选、字段缺失返回 null、成本来源和不返回敏感字段。
- 悬浮窗设置接口必须验证默认值、透明度/刷新间隔边界、保存时保留其他设置段和 show/hide/toggle 行为。
