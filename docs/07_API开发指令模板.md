# 07 API 开发指令模板（操作手册）

> ⚙️ **新模式（2026-08-13）**：本项目改由 **agent 自驱开发 + 自动测试为 Gate**。本文档从「人喂 prompt 给 API」转为「agent 的执行协议」：§1 骨架 = agent 每个里程碑的内部执行清单；§2 各里程碑卡的「验收 checklist」= 自动测试通过条件；附录A CCR / 附录B 交付块仍由 agent 在自驱过程中产出并留档。01~06 契约内容不变。
>
> （旧说明，备查：这曾是驱动方把任务喂给 API 的操作手册——复制 §1 通用骨架 + §2 对应里程碑卡，组合成 prompt 粘贴给 API，再按验收 checklist 验收。）

## §1 通用 Prompt 骨架（每个里程碑都用）

```
你是「2xapi Codex Console」项目（Tauri + Rust/axum + 原生 JS/CSS）的开发者。
本次只实现【里程碑 {{MX}}：{{名称}}】。

【开始前必读并严格遵守】
- docs/00_开发流程总纲.md，尤其是 §5「AI 协作纪律」（强制）。
- 本次「输入文档」列出的契约章节。

【五条铁律】
1) 契约冻结：02 数据模型 / 04 接口 / 01 行为矩阵不得擅自偏离。发现契约缺陷 → 停止实现，按附录A发 CCR，待确认后先改契约再实现。
2) 单里程碑闭合：只做下方「范围」内的任务，不读取/不实现下一里程碑的任何内容。
3) 错误分支必填：每个接口/网关路径覆盖 超时/401/403/不可达/协议不兼容/上游4xx·5xx。
4) 依赖白名单：只引入 axum/reqwest/serde/serde_json/toml/tower/tokio/uuid/chrono；新增须在 CCR 说明。
5) 中文注释说明业务意图；命名与契约字段对齐。

【输入文档】（以下契约内容作为本次实现的唯一依据，逐字段匹配）
{{粘贴：相关文档章节}}

【范围】只做以下任务，不扩展：
{{粘贴：05 中该里程碑的任务表}}

【交付】提交时必须含三件，缺一视为未完成（见附录B）：
1) 变更文件清单
2) 自检报告：下方 DoD 逐条打勾并说明
3) 可复现证据：测试命令+实际输出 / curl 返回 / 截图

【完成后】停下，等我按「验收 checklist」验收。不要自行开始下一里程碑。
```

> **拼装示例**（M2）：取 §1 骨架 → 填 `MX=M2 名称=Config 写入引擎` → 粘贴 01 §4/§6 + 02 §5 作为输入文档 → 粘贴 05 的 M2 任务表 → 末尾附 §2.M2 的 DoD 与验收 checklist。

## §3 附录A — 契约变更请求（CCR）模板

> 发现契约（02/04/01矩阵）有缺陷或矛盾时，**先发 CCR 再实现**，不要自行其是。

```
【CCR-序号】例如 CCR-007
契约位置：02 §5.2 / 04 §1.3 / 01-矩阵#9 ...
发现的问题：<具体描述，引用原文>
与哪些决策/FR 冲突：<如 与 01-D3 冲突>
建议变更：<改成什么>
影响里程碑：<M?；是否影响已完成的 M?>
等待确认后再实现。
```

## §5 附录C — 验收通用项（每个 Gate 都查）

- [ ] 交付三件齐全（清单/自检/证据）
- [ ] 自检报告中无未勾选项
- [ ] 数据/接口/产物与冻结契约逐字段一致
- [ ] 错误分支已被测试覆盖
- [ ] 无 P0（崩溃/数据丢失/契约违背）/ P1（核心功能不可用）
- [ ] 未引入白名单外依赖
- [ ] 未实现范围外功能（建议类记入 08 建议池，不混入）

不满足 → 按 00 §6 回退流程处理，不进入下一里程碑。
