## §2 接入模式选择器（编辑表单顶部）

```
┌─────────────┐ ┌─────────────┐ ┌────────────┐
│ ○ 官方登录   │ │ ● 保持官登  │ │ ○ 第三方API │
│  Official   │ │  +API Mixed │ │  PureApi   │
└─────────────┘ └─────────────┘ └────────────┘
选 Mixed/PureApi 时下方显示连接字段；选 Official 时连接字段折叠隐藏。
```

**联动规则**：
- `Official`：隐藏 base_url、api_key、wire_api、proxy_url、模型表格；仅保留 name/model（model 可留默认）。
- `Mixed`/`PureApi`：显示全部；选 PureApi 时在表单底部显示提示「将覆盖 auth.json，官方登录会备份，可一键恢复」。

## §3 编辑表单

| 元素 | 字段 | 校验 | API |
|---|---|---|---|
| 名称 | name | 必填 1~40 | POST/PUT `/api/providers` |
| 接入模式 | access_mode | 三选一 | §2 |
| 上游地址 | base_url | 合法 URL，非 Official 必填 | — |
| API Key | api_key | 非 Official 必填，密码框+显隐 | — |
| 协议 | wire_api | Responses/ChatCompletions | — |
| 默认模型 | model | 必填，建议来自 models | — |
| 高级(折叠) | proxy_url/timeout_secs/user_agent/custom_headers/website/notes/icon | timeout 5~3600 | — |
| 模型表格 | models[] | 增删改行 | — |
| 拉取模型 | 按钮 | 调 fetch-models 填充表格 | POST `/api/providers/fetch-models` |
| 预览 | 按钮 | 打开 §5 预览面板（用当前表单值） | POST `/api/providers/preview-config` |
| 保存 | 按钮 | 先校验再保存 | POST/PUT |
| 取消 | 按钮 | 未保存改动二次确认 | — |

**模型表格列**：name｜display_name｜context_window｜is_multimodal☑｜send_as_is☑｜删除。

## §4 激活 / 切官方

| 元素 | 行为 | API |
|---|---|---|
| 激活按钮（列表项/详情） | 确认后激活，刷新顶栏 active；显示 activate 返回的三布尔结果（写入/改auth/备份） | POST `/api/providers/activate` |

| 状态反馈 | toast：成功 / 失败原因（取 error.message） | — |

## §5 Config 预览面板

```
┌─ config.toml 预览（只读）─────────────────────┐
│ model_provider = "custom"                      │
│ model = "deepseek-v4-flash"                    │
│ [model_providers.custom]                       │
│ base_url = "http://127.0.0.1:8787"             │
│ ...                                            │
└────────────────────────────────────────────────┘
auth.json: [将设置 OPENAI_API_KEY]   备份: [将创建 .official.bak]
```
- 数据来自 `preview-config`；`auth_action=noop` 时不显示 auth 行。
- 文案映射：`backup_will_create` → 「将创建 .official.bak」/「已存在备份，不覆盖」。

## §6 诊断面板（Provider Doctor）

```
Step1 配置校验      ✓ 通过
Step2 连接测试      ✓ 通过   延迟 142ms   模型 12 个
Step3 真实请求      ✓ 通过
─────────────────────────
[重新诊断]
```
- 失败步显示 ✗ + error.message；errors[] 全部列出。
- 三步进行中显示 spinner；不阻断（FR-6 顺序但汇总）。
- 数据：POST `/api/providers/diagnose`。

---

## §7 交互/状态规则

- 所有请求经 `api-client.js`，统一处理 `{ok,data}`/`{ok:false,error}`，失败弹 toast。
- active 状态变更后，刷新 `/health` 以同步顶栏 access_mode。
- 表单未保存离开 → 二次确认。
- key 等敏感字段默认掩码，编辑时不回填原值（占位 `••••`），未改则不提交该字段（后端保留原值）。
- 删除 active 项 → active=null，顶栏提示「未激活」。
